# Определения метрик

Период сеансов: 1 марта - 31 июля 2024 года. Модель содержит один билетный факт, витрину с одной строкой на сеанс и витрину с одной строкой на покупателя.

| Объект | Единица учёта |
|---|---|
| Билет | Одна строка `films_payments`. Фактический проход в зал не подтверждается. |
| Сеанс | `session_date + part_of_day + cinema_id + cinema_room_id`. |
| Клиент | Уникальный `client_id` с покупкой билета в предоставленном периоде. |
| Частота клиента | Число уникальных сеансов с покупкой, не число строк платежей. |
| Строка бара | Товарная запись после объявленной политики совпадений. Не подтверждённый чек или заказ. |

## Формулы и агрегация

| Показатель | Формула |
|---|---|
| Билетная выручка | `SUM(session_revenue)`, по одной строке на сеанс, после скидки. |
| Билеты | `SUM(session_tickets_sold)`. |
| Доступные места | `SUM(count_seats)` по всем выбранным сеансам. |
| Заполняемость, % | `100 * SUM(session_tickets_sold) / SUM(count_seats)`. |
| Средняя заполняемость сеанса, % | `AVG(occupancy_rate_session)`; отличается от взвешенной заполняемости. |
| Выручка на доступное место | `SUM(session_revenue) / SUM(count_seats)`. |
| Выручка на сеанс | `SUM(session_revenue) / COUNT(session_key)` на сеансовой витрине. |
| Доля онлайн-билетов, % | `100 * SUM(online_tickets) / SUM(session_tickets_sold)`. |
| Выручка на клиента за период | `SUM(total_revenue_with_bar) / COUNT(client_id)` на клиентской витрине. |
| Билетная выручка клиента на сеанс с покупкой | `total_ticket_revenue / sessions_visited`; бар к визиту не приписывается. |

При агрегации сети/кинотеатра используется отношение сумм. Нельзя суммировать выручку на место или усреднять проценты без учёта необходимого веса.

## Клиентские группы

- `1 сеанс`: один уникальный сеанс с покупкой за период - 9 504 клиента.
- `2–3 сеанса`: два или три - 69 клиентов.
- `4+ сеанса`: четыре и более - 0 клиентов.

История до периода неизвестна. Один сеанс не означает, что клиент новый; у клиентов конца периода меньше времени для повторной покупки. 654,89 ₽ - накопленная выручка на клиента за период. Групповые 650,03 ₽ и 1 324,49 ₽ не являются сравнением среднего чека визита.

## Очистка бара

Правило `exact` соответствует исходному учебному проекту: `drop_duplicates()` по четырём полям `client_id, pay_at, name, price`, сохраняется первая строка.

| Показатель | До очистки | После очистки |
|---|---:|---:|
| Товарные строки | 16 875 | 14 941 |
| Сумма, ₽ | 3 786 431 | 3 393 237 |

Удалено 1 934 совпадения на 393 194 ₽. Это влияние выбранного правила, а не независимое доказательство технического задвоения: идентификатора позиции/заказа и количества товара нет. Для оценки чувствительности можно выбрать `preserve`.

В основной витрине `bar_item_rows_count` означает число товарных строк, `bar_avg_item_price` - среднюю цену позиции. В файле совместимости DataLens старые имена `bar_orders_count`/`bar_avg_check` сохранены только как технические псевдонимы, не как определения заказов и среднего чека.

## Фильтры и календарь

Билетные показатели фильтруются по сеансам: кинотеатр, зал, фильм, месяц и тип зала. Бар не содержит кинотеатра/сеанса; его нельзя точно распределить по этим срезам. Клиентские показатели показаны по сети за полный период. При сравнении с текущим срезом следует учитывать эту разницу охвата.

Для сеансов применяется `session_date`. Для платежей отдельно строится `monthly_payments.csv` по `pay_at`. Даты сеансов начинаются 1 марта, оплаты билетов - 13 февраля. CSV не содержит смещения часового пояса; сборка предполагает `Europe/Moscow`. Выводы по времени суток основаны на `part_of_day` расписания.

## Проверки и ограничения

Сборка начинается с полного расписания и сохраняет нулевые продажи. В предоставленном расписании 1 963 сеанса, все с продажами. Подтверждённая заполняемость AC1/AC2/AC3 - 19,65% / 23,34% / 22,20%.

Проверены уникальность ключей, соответствия продаж, сохранение числа строк при JOIN, вместимость, диапазоны скидок и цен, сверка выручки и билетов между слоями. Итог — [raw_quality_report.json](../results/raw_quality_report.json).

Истории цен/скидок на момент каждой продажи нет: расчёт использует справочники. Затраты, маржа и фактические посещения отсутствуют. Поэтому выручка не интерпретируется как прибыль, покупка — как посещение, а описательные различия — как причинный эффект.
